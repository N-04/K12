# K12 文档智能处理工具

最后维护时间：2026-06-29 17:01:45 CST

K12 是一个本地优先的文档处理工作台原型，按 PRD 覆盖 Word、Excel、PPT、PDF 的上传识别、任务队列、公式预检、OMML 能力位、宏编排、微小图片检索、报告导出和本地/网页混合模式状态。

当前版本使用 Python 标准库后端和静态前端，不依赖外网安装包。Office、MathType、OMML 转换、Word 宏执行等强本机能力被封装为清晰的本地客户端能力位，便于后续按 Windows 与 macOS 分别接入本地处理服务。

## 运行

```bash
make run
```

打开：

```text
http://127.0.0.1:8765
```

## 测试

```bash
make test
```

## 项目结构

```text
k12/              本地 API、数据模型、任务处理与报告生成
static/           无构建前端工作台
tests/            标准库 unittest 测试
docs/             架构与首版范围说明
.k12-data/        运行时 SQLite、报告与输出目录（不入库）
```

## 当前首版范围

- 文件元数据导入、格式分类、基础校验，并在文件列表展示大小、页数/幻灯片数/工作表数、MathType/图片/微小图/OMML 缺失等能力标记，以及不支持、损坏、加密、过大等校验失败原因。
- 拖拽上传真实文件到本地 `.k12-data/uploads/`，拖入文件夹会递归读取子文件，文件夹上传会保留浏览器提供的来源相对层级，ZIP 上传后自动识别压缩包内支持的文档条目。
- 上传和元数据导入支持重复文件策略：自动重命名、跳过和覆盖。
- 文件列表操作列直接提供详情、预览、转换、检索、源文件下载、关联报告入口、重新上传替换和删除入口；转换/检索会按当前文件自动创建推荐任务，报告入口会读取 `/api/files/{file_id}/reports` 并跳转到报告中心，替换和删除需要 `files.manage` 权限，任务创建需要 `tasks.create` 权限。
- 文件列表支持已选文件和当前筛选类型打包下载，ZIP 内包含源文件和 `manifest.csv`。
- 文件删除会移除本地上传缓存和 ZIP 解压出的子文件记录，但不会删除用户外部路径中的原始文档。
- 文件列表支持重新上传替换，替换后保留原 `file_id`，重新分析新文件类型、公式、宏、加密和预览信息。
- 加密文件会提示输入打开密码；密码只保存在当前本地服务进程内，文件记录只保存“已登记”状态。
- 工作台首页展示支持格式说明、10 个快捷功能入口和最近任务列表，快捷功能覆盖 Word/PPT/PDF 转换、MathType/OMML/宏、PDF 公式识别、微小图片检索和批量处理；顶部菜单页按 PRD 菜单结构集中展示首页、文件处理、Word、宏、公式、图片、批量、本地客户端、网页管理、预览、报告和系统设置入口。
- 单文件和批量任务创建、任务详情、进度、耗时、成功/失败数量、失败原因、日志、暂停、继续、重试、取消和可确认的任务完成提醒；服务重启后会把遗留处理中任务标记为可恢复，用户可继续执行，`/api/tasks/recovery-summary` 会返回中断、暂停、失败和可重试任务的脱敏恢复清单；批量任务会使用工作台并发数量和失败策略，任务详情展示批量单文件进度，批量报告会记录每个文件的状态、失败原因、建议任务、可重试标记、跳过状态、最大并发、失败策略和遇错继续策略，失败文件可通过任务接口或最近报告操作跳过并重建报告。
- 工作台处理流程通过左侧线条图标拖拽调整顺序，也支持焦点停在手柄时用方向键或 Home/End 调整位置；未手动选择任务类型时，“开始处理”会使用当前流程第一项，并把规范化后的流程顺序写入任务参数和报告质量检查。
- 安全与隐私面板按 PRD 第 13 章核查文件安全、宏安全、本地通信安全、隐私保护、离线和私有化状态。
- 兼容性矩阵按 PRD 第 15 章核查操作系统、Office、公式、宏和模式兼容性，明确 Windows/macOS MathType 对象不通用时的 MathML、LaTeX 和图片兜底策略。
- 技术架构面板按 PRD 第 16 章读取 `/api/architecture`，展示当前 Python 本地 API、静态前端、SQLite/文件目录、接口合同、FastAPI/Django/队列/真实引擎后续接入边界。
- 开放 API 面板读取 `/api/api-catalog`，列出健康检查、文件、任务、报告、日志、设置、能力、安装画像、本地任务载荷和本地状态同步等接口的路径、方法、鉴权要求和敏感标记。
- 产品总结面板读取 `/api/product-summary`，按 PRD 第 21 章展示 13 条核心能力、已落地/合同覆盖/规划中状态，以及 Windows 本地桌面版、网页管理端、混合模式和 V3 能力增强四阶段路线。
- 智能增强规划面板读取 `/api/enhancement-plan`，按 V3.0 展示 AI 排版修复、智能模板套用、私有化部署、开放 API 和质量反馈闭环的输入、授权和风控边界；AI 与模板套用不声明真实执行。
- 文件处理页右侧提供可见的结果预览面板，集中展示当前文件详情、结构化预览和本地能力状态；结构化预览支持 Word、PPT、Excel、PDF、图片和 ZIP 的页面、对象、告警摘要，并在页段上显示公式、OMML、MathType、宏、微小图片和低置信度对象标记，支持预览搜索、告警/对象/标记点击定位、命中高亮、翻页和缩放。
- 转换报告支持转换前后对比预览，可对比源文件和转换产物的页段、对象数量、告警和预览摘要。
- 排版校正支持在报告页按报告记录页码、标题层级、表格结构、图片位置、公式位置和公式编号问题，保存修复前后描述、建议和处理状态；公式位置丢失时会写入异常位置并进入失败清单和质量检查。
- Word/PPT/PDF/Excel 转换任务的本地优先流程。
- Word 转 PPT 与 PPT 转 Word 会生成最小可用的 `.pptx` / `.docx` 转换产物，并在任务中心提供下载；Word 转 PPT 会在 artifact 和报告中写入图片、表格、OMML、MathType 的对象保留清单，PPT 转 Word 会按逐页讲义、内容提取、图文混排、备注优先和大纲模式写入目录、标题、正文、备注、Word 模板名、图片/表格/图表对象摘要和公式数量，并把 PPT 公式写入统一公式报告。验收矩阵会用临时 DOCX 自检 Word 图片、表格、OMML 和 MathType/嵌入对象是否进入 PPTX 对象保留清单，也会用临时 PPTX 自检公式文本、MathType 和 Equation Native 线索识别；复杂排版、MathType 对象和 OLE 写回仍需本地客户端复核。
- 转换页提供 PPT 转 Word 工作区，集中展示 PPT 缩略结构、内容预览、备注/图片/公式提取设置和最近 Word 输出，可一键选择 PPT 后创建转换任务。
- Excel 转 PDF 会按全部工作表、当前工作表、选区或 API 指定 sheet 提取工作表、公式、单元格、图表、图片和批注摘要，并可选择保留公式、仅保留计算结果或拆分工作表为多个文件，生成可下载的 `.pdf` 转换产物。
- Excel 转 Word 与 Excel 转 PPT 会按全部工作表、当前工作表、选区或 API 指定 sheet 提取工作表、单元格、公式、图表、图片和批注摘要，并可选择保留公式、仅保留计算结果或拆分工作表为多个文件，生成可下载的 `.docx` / `.pptx` 转换产物。
- 转换设置支持 Word 转 PPT 模板、每页字数、自动分页、目录页、保留公式、先转 MathType、演讲者备注、自动美化、PPT 转 Word 模式、PPT 转 Word 的 Word 模板、目录开关、备注提取、图片提取和公式提取、PDF 精度模式、Excel 转换范围、保留图片、表格、页眉页脚、脚注尾注、批注和修订标记；转换输出会记录设置快照并写入报告。
- 转换产物默认写入 `.k12-data/outputs/{task_id}/`，也可通过设置页的输出目录改到指定位置；输出同名策略支持自动重命名、跳过和覆盖。
- 基础设置支持保留原文件和任务完成后打开输出目录；网页端只记录本地客户端动作意图，不直接打开任意本地路径。
- PDF 转 Word 按 Mathpix OCR API 设计，上传分析会识别文本型、扫描型、混合型、含图片、含公式和含表格线索，并为每个 Mathpix 作业记录识别计划、图片/表格/公式保留计划，支持提交 PDF、轮询状态、下载 DOCX 和保存 Mathpix `tex.zip` 公式识别结果包；公式 OCR 开启时，任务会进入混合模式，并把 PDF 公式 MathType 后处理交给本地客户端动作队列。
- 转换页提供 PDF 转 Word / Mathpix 工作区，集中展示 PDF 类型、OCR 建议、文字/公式/表格 OCR 状态、识别计划、保留计划、Mathpix 作业队列、低置信度 PDF 公式和最近 Word 输出，并可一键选择 PDF 后创建导出 Word 任务；`/api/mathpix-jobs` 只汇总报告中的 Mathpix 状态，不会触发新的外部上传。
- 转换页提供 Word 处理工作区，集中展示 Word 文件预览、公式/OMML/MathType 检测、宏检测结果和最近 Word 处理报告入口，可直接选择 Word、预览和创建 Word 转 PPT 任务。
- Word 公式预检、OMML 依赖检索、MathType 格式化、宏顺序执行的 API 合同。
- 公式报告支持来源、位置、原始截图引用、LaTeX、MathML、MathType 预览、格式化前后对比、格式化失败兜底、置信度、状态明细和默认输出偏好；已有 MathType 来源公式会按原对象保留策略记录，并进入对象保留清单自检；LaTeX 来源公式会生成 MathML 兜底和 MathType 预览，验收矩阵会用自检证明该链路，原生 MathType/OLE 对象写回仍需本地客户端；疑似图片公式识别失败时会标记待确认并保留原图引用，MathType 格式化关闭或失败时会保留原公式。设置页可配置公式输出格式、字体、字号、格式化范围、对齐、变量/函数样式、上下标比例、分式/根式/矩阵/希腊字母样式、行内基线、独立公式间距、编号方式、低置信度阈值、处理策略和是否保留公式原图；任务选项可覆盖公式格式化范围，验收矩阵会自检全文批量、当前章节、选中区域和单个公式范围参数。
- 公式页支持列表与详情校正工作区，详情区集中展示原始公式截图引用、LaTeX 编辑、MathType 预览、MathML/OMML 转换结果、格式化参数、置信度和格式化前后对比；公式页也支持导出公式 ZIP，包含 `formulas.json`、`formulas.tex`、`formulas.mml`、逐条公式文件和 `manifest.csv`，也支持按报告导出公式结果 XLSX。
- OMML 转 MathType 任务会先记录用户是否确认将 Word 自带公式转换为 MathType；默认未确认时写入“需确认”提示，用户选择转换后再交给本地客户端执行。任务会检索 OMML 依赖文件，按复制策略放到当前 Word 文档目录，并更新文件列表的 OMML 缺失状态后写入报告。
- OMML 校正支持按报告记录转换失败、保留 OMML、重新转换、已修复和手动指定依赖路径；主界面 OMML 依赖卡片可直接标记保留、重新转换、已修复或指定依赖文件，并可导出 OMML 转换失败清单 CSV，记录可随报告删除一并清理。
- 宏处理支持用户选择宏、按名称/来源/用途/最近使用筛选宏、查看宏详情、通过拖拽手柄或上/下移图标调整执行顺序、保存/加载顺序模板、确认风险、创建备份、执行超时、批量执行控制、失败后停止/跳过/继续/询问策略、禁用宏执行队列、白名单宏控制、从任务中心恢复宏执行前备份；宏页展示宏执行日志，宏执行报告卡片可重新创建单个宏的本地执行任务，也可载入报告中的宏顺序供调整后重新执行、导出宏执行失败清单 CSV，并生成本地客户端待执行队列。验收矩阵会用临时 `.docm` / `.dotm` 文件自检 Word 文档和模板宏启用容器检测，也会用临时 `.docm` 文件自检同一宏顺序可应用到多个 Word 文件；真实 VBA 模块枚举和执行仍需本地客户端。
- 微小图片检索会从 Word/PPT/Excel 的 OOXML 媒体目录提取真实图片，也会读取 PDF 图片 XObject 的宽高、Filter 和可导出流，按阈值生成缩略图和报告；设置页可控制最大面积、页眉页脚、水印、透明图、重复图和导出格式。
- 图片报告支持按报告导出图片 ZIP 与微小图片清单 XLSX，清单记录宽高、面积、图片格式、疑似类型、人工确认类型、页眉页脚、水印、透明、重复状态、重复判断状态、导出状态和异常兜底；图片提取失败会进入失败清单、质量检查和异常处理面板，重复判断失败或无法判断时保留原始结果，并可按疑似类型、文件来源、位置关键词、面积和重复状态筛选；图片页提供详情面板集中查看缩略图、位置、尺寸、面积、类型判断、标注状态和导出状态，可定位回来源文件预览，定位失败会标记为“位置未知”，导出失败可从来源文档重新导出，也可确认图片类型、标记误判、删除待处理和替换待处理；替换会登记用户选择的替换图片素材、大小和 hash，等待本地客户端改写源文档。
- 公式/宏/图片/质量报告的结构化输出，质量检查覆盖文件校验、结构数量、内容保留、转换前后预览一致性、公式置信度、公式位置异常、OMML 依赖、宏执行、微小图片、转换输出和 Mathpix 状态；预览一致性会比较源文件与成功转换产物的页段数、对象数量、对象减少项和告警数量。质量摘要会集中列出处理文件、OMML、MathType、格式化公式、宏、低置信度公式、公式位置异常、图片、微小图片、表格、可能丢失对象、错误详情和修复建议；Mathpix 报告会展示 OCR 开关、来源线索和图片/表格/公式保留计划，支持 HTML、JSON、PDF、XLSX、TXT 下载。
- OCR 设置支持文字 OCR、公式 OCR、表格 OCR、语言、精度模式和速度模式；PDF 转 Word 的 Mathpix 请求会把 DOCX、`tex.zip` 等真实输出格式放入 `conversion_formats`，并将 K12 的 OCR 开关、语言、精度和速度模式写入安全审计元数据。全部 OCR 关闭时不会上传文件。
- 报告中心支持独立下载失败清单 CSV，覆盖文件校验、批量处理、OMML、宏、转换输出和 Mathpix 失败。
- 报告中心支持删除单份报告，删除报告缓存、图片缓存和人工标注，但保留源文件、任务记录和转换输出。
- 任务日志支持全局查看、按任务查看和 TXT/LOG/CSV/JSON 导出，任务中心可切换到单个任务日志并导出该任务日志；任务结果包也会附带任务级日志；日志可按上传、转换、公式、OMML、宏执行、图片和错误分类开关写入。
- 系统设置和本地客户端连接状态展示。
- 系统维护支持设置历史/日志保留天数，并清理旧任务、旧报告、日志、输出、备份和图片缓存，不删除上传源文件库。
- 隐私设置支持关闭历史记录；关闭后任务仍会执行并返回状态，但完成后不保留任务、报告、日志和运行缓存，上传源文件库保留。
- 本地 API 支持安全令牌；令牌留空时不拦截，设置后 JSON 请求、上传和下载都需要携带令牌。
- API 响应默认隐藏 `storage_path`、`file_path`、报告产物路径、备份路径和图片路径；设置页开启“显示本地路径”后才返回真实路径。
- 结构化安装画像接口 `/api/install-profile`，按 Windows/macOS 展示安装包、必装组件、预检项、任务分流和 MathType 兼容风险；安装计划接口 `/api/install-plan` 会返回 `.msi` / `.pkg` 包状态、SHA256 校验、安装步骤、客户端心跳平台匹配状态和 `formula_compatibility` 公式交付合同，明确 Windows/macOS MathType 原生对象不跨平台兼容以及 MathML、LaTeX、图片兜底格式，只有本地 `installers/` 目录存在真实安装包时才开放 `/api/installers/{file_name}` 下载。

## Mathpix PDF 转 Word

PDF 转 Word 的识别引擎固定为 Mathpix；即使通过 API 写入其他引擎值，后端也会归一为 Mathpix。出于 PRD 的隐私和第三方上传安全要求，系统不会默认上传文件；需要在设置页开启“授权外部上传”，并在运行服务的环境里配置：

```bash
export MATHPIX_APP_ID="你的 APP ID"
export MATHPIX_APP_KEY="你的 APP KEY"
```

运行预检会检查上述环境变量是否存在，只展示环境变量名，不回显 APP ID 或 APP KEY 的实际值。

如果全局设置或任务参数开启“等待识别完成”，任务会轮询 Mathpix 状态并在完成后下载 DOCX 到当前输出目录的 `{task_id}/` 子目录，同时保存 Mathpix `tex.zip` 公式识别结果包。等待轮询可以由任务参数请求，但外部上传授权只读取设置页的“授权外部上传”，任务参数不能临时放开上传。DOCX 和公式包都会写入标准转换输出，可在任务中心直接下载或随任务结果包一起打包。系统会从 Mathpix 的 `.tex` 文件中提取 PDF 公式，支持行内公式、展示公式、equation/align/gather/multline 环境和纯 TeX 公式行，并写入公式报告和统一公式导出包。

每个 Mathpix PDF 作业都会记录 `recognition_plan`、`retention_plan`、`task_option_audit` 和脱敏 `request_options`，包含外部上传授权状态与授权来源、等待轮询来源、凭证环境变量名、是否允许提交、PDF 类型、图片对象数、表格线索、公式线索、文字/公式/表格 OCR 开关、Mathpix 输出格式、表格 fallback 和审计元数据键，以及图片、表格、公式的保留状态。`task_option_audit` 使用 `k12.mathpixTaskOptionAudit.v1`，会列出被忽略的 `allowExternalMathpixUpload`、`externalUploadAuthorized` 等任务参数授权键，同时声明授权来源仍只能是 `settings.allowExternalMathpixUpload`。`recognition_plan.download_manifest` 会把 DOCX 和公式 OCR 开启时的 `tex.zip` 标记为必需输出，逐项记录已下载、跳过、失败或待处理状态、哈希可用性和失败原因，不暴露本地路径；`recognition_plan.formula_review` 会同步公式置信度阈值、低置信度处理策略、原图保留策略和人工校正接口，Mathpix `tex.zip` 公式低于阈值时会进入待确认；公式重识别标注会写入 `k12.formulaRecognitionRequest.v1`，只登记 Mathpix 授权/凭证门槛或本地客户端门槛，不由任务参数临时授权外部上传。外部上传未授权或 OCR 全部关闭时也会生成该计划用于报告复核，但不会提交 PDF。

## OMML 依赖检索

Word 文档检测到 OMML 公式后，文件列表会显示“OMML缺失”状态。`公式预检`、`OMML 转 MathType`、`Word 转 PPT` 和 `MathType 格式化` 任务会写入“OMML 转换确认”记录，标明是否已选择转换为 MathType、是否保留原公式、决策来源和依赖状态；未确认时本地客户端载荷会保持等待确认。任务会尝试查找 `OMML2MML.XSL` 等 OMML 依赖文件。检索范围包括当前文档目录、K12 运行目录、常见用户目录和设置页填写的自定义路径；也可以在设置页手动指定一个 OMML 依赖文件。复制策略支持覆盖、跳过和自动重命名。验收矩阵会用临时目录自检搜索和复制逻辑，不触碰用户文件；OMML 转 MathType 对象写回仍交给本地客户端实测。

## Word 宏安全队列

宏处理默认不会在网页端直接执行 Word 宏。用户可以在宏页选择宏并调整顺序，把常用顺序保存为模板，确认风险后创建任务；系统会先备份本地 Word 文件，然后把宏队列写入报告，状态标记为“待本地客户端执行”。验收矩阵会用临时 `.docm` 文件证明宏顺序可进入本地动作队列、桌面计划包含 `macro.run_ordered`、dry-run 可回传就绪摘要，并证明同一宏顺序可下发给多个 Word 文件，不创建用户文件备份。后续接入 Windows 本地客户端后，可由本地 Office COM 执行队列。

设置页可以关闭宏检测、关闭宏执行队列、按当前文档宏/模板宏/本地宏库分别授权，或启用“仅允许白名单宏”。宏失败策略会写入本地客户端队列，支持失败后停止队列、跳过当前宏、继续后续宏或暂停询问用户。宏被禁用、来源未授权或不在白名单时，系统只写入安全报告，不创建执行前备份，也不会把该宏交给本地客户端。

任务中心的“恢复”按钮会把宏执行前备份复制回原文件路径。恢复只接受 `.k12-data/backups/` 下由当前任务记录的备份文件，避免任意路径覆盖。

## 本地伴随 CLI

当前仓库提供一个标准库本地伴随客户端入口，用于验证本地 + 网页交接链路：

```bash
K12_LOCAL_TOKEN="你的本地安全令牌" python3 -m k12.local_client --origin http://127.0.0.1:8765 --sync-dry-run
```

也可以生成原生执行请求合同，供后续 Windows 本地执行器接入：

```bash
K12_LOCAL_TOKEN="你的本地安全令牌" python3 -m k12.local_client --origin http://127.0.0.1:8765 --native-plan --allow-native-execution
```

OMML 依赖复制这类本地文件动作需要单独显式授权：

```bash
K12_LOCAL_TOKEN="你的本地安全令牌" python3 -m k12.local_client --origin http://127.0.0.1:8765 --execute-file-actions
```

安装为包后也可使用：

```bash
k12-local-client --origin http://127.0.0.1:8765 --sync-dry-run
```

该 CLI 会读取 `/api/local-client/manifest`、发送 `/api/local-client/heartbeat`、领取 `/api/tasks/{task_id}/local-payload`，并可选择通过 `/api/tasks/{task_id}/local-sync` 回传 dry-run 状态。心跳会附带 Windows/macOS 组件预检摘要，包含 Office、MathType、LibreOffice 和 OMML 依赖的可见状态与能力位，但不回传任何安装路径。dry-run 会生成 `k12.localDryRunExecution.v1` 摘要，逐个动作记录 gate、所需能力、步骤数量、输出类型和等待/阻塞原因。`--native-plan` 会生成 `k12.localNativeExecutionRequest.v1`，列出同平台、能力门槛、操作步骤、平台执行器画像和阻断原因：Windows 标记为后续 pywin32/Office COM 适配器合同，macOS 标记为受限交接合同，只保留同平台 MathType 边界、人工复核和 MathML/LaTeX/图片兜底，不声明已能原生写回。`--execute-file-actions` 会生成 `k12.localFileActionExecution.v1`，目前只执行 OMML 依赖复制等安全本地文件动作，且目标必须是当前文档所在目录。当前 CLI 不执行 Office、MathType、OMML 写回或 Word 宏，也不会在输出摘要里打印本地文件路径或令牌。

## 系统维护

设置页可配置自动清理临时文件、历史保留天数、日志保留天数和清理周期天数。开启自动清理后，本地服务启动时会检查上次清理时间，超过周期才执行清理。手动“清理历史”会删除超过保留期的任务、报告、日志、报告文件、输出目录、宏备份目录和图片缓存目录，但会保留文件库记录、上传源文件和外部原始文档路径。

## Windows 与 macOS 安装差异

设置页可选择本地客户端平台，并会即时刷新安装画像。Windows 安装画像优先使用 Microsoft Office COM、pywin32 和 Windows MathType 自动化；macOS 安装画像会标记 Office 自动化受限，优先走本地文件分析、人工确认和公式兜底格式。Windows 与 macOS 的 MathType 公式对象不通用，跨平台交付建议同时保留 MathML、LaTeX 或图片兜底。安装包下载会校验目标平台，并在响应头中返回安装包边界、MathType 原生对象同平台边界和 ASCII 兜底格式标识；中文兜底格式清单保留在安装计划 JSON 合同中。运行预检会对 OMML/MathType 相关任务给出兼容提示：平台专属对象模式需确认，MathML/LaTeX 或图片兜底模式通过；如果安装计划目标平台与本地客户端心跳平台不一致，运行预检会标记失败，本地任务交接会显示“平台不符”并要求切换客户端或使用兜底格式。

## 本地 API 安全

默认监听 `127.0.0.1`，设置页的“本地安全令牌”留空时保持无令牌模式。填写令牌并保存后，前端会把令牌保存在浏览器本地存储，后续 API、上传、报告下载、图片资源和任务打包下载都会自动携带该令牌。

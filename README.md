# K12 文档智能处理工具

最后维护时间：2026-06-23 17:33:02 CST

K12 是一个本地优先的文档处理工作台原型，按 PRD 覆盖 Word、Excel、PPT、PDF 的上传识别、任务队列、公式预检、OMML 能力位、宏编排、微小图片检索、报告导出和本地/网页混合模式状态。

当前版本使用 Python 标准库后端和静态前端，不依赖外网安装包。Office、MathType、OMML 转换、Word 宏执行等强本机能力被封装为清晰的本地客户端能力位，便于后续按 Windows 与 macOS 分别接入本地处理服务。

## 运行

```bash
make run
```

```text
http://127.0.0.1:8765
```

```text
docs/             架构与首版范围说明
.k12-data/        运行时 SQLite、报告与输出目录（不入库）
```

## 当前首版范围

- 文件元数据导入、格式分类、基础校验。
- 拖拽上传真实文件到本地 `.k12-data/uploads/`，ZIP 上传后自动识别压缩包内支持的文档条目。
- 上传和元数据导入支持重复文件策略：自动重命名、跳过和覆盖。
- 文件列表支持源文件下载，上传缓存、ZIP 解压条目和可访问的本地外部路径都走本地令牌保护下载。
- 文件列表支持已选文件和当前筛选类型打包下载，ZIP 内包含源文件和 `manifest.csv`。
- 文件删除会移除本地上传缓存和 ZIP 解压出的子文件记录，但不会删除用户外部路径中的原始文档。
- 文件列表支持重新上传替换，替换后保留原 `file_id`，重新分析新文件类型、公式、宏、加密和预览信息。
- 加密文件会提示输入打开密码；密码只保存在当前本地服务进程内，文件记录只保存“已登记”状态。
- 单文件和批量任务创建、进度、日志、暂停、继续、重试、取消；服务重启后会把遗留处理中任务标记为可恢复，用户可继续执行；批量报告会记录每个文件的状态、失败原因、建议任务和可重试标记。
- 文件结构化预览，支持 Word、PPT、Excel、PDF、图片和 ZIP 的页面、对象、告警摘要。
- Word/PPT/PDF/Excel 转换任务的本地优先流程。
- Word 转 PPT 与 PPT 转 Word 会生成最小可用的 `.pptx` / `.docx` 转换产物，并在任务中心提供下载。
- Excel 转 PDF 会提取工作表、公式和单元格摘要，生成可下载的 `.pdf` 转换产物。
- Excel 转 Word 与 Excel 转 PPT 会提取工作表、单元格和公式摘要，生成可下载的 `.docx` / `.pptx` 转换产物。
- 转换设置支持 Word 转 PPT 模板、PPT 转 Word 模式、PDF 精度模式、Excel 转换范围、保留图片、表格、页眉页脚和批注；转换输出会记录设置快照并写入报告。
- 转换产物默认写入 `.k12-data/outputs/{task_id}/`，也可通过设置页的输出目录改到指定位置。
- 基础设置支持保留原文件和任务完成后打开输出目录；网页端只记录本地客户端动作意图，不直接打开任意本地路径。
- PDF 转 Word 按 Mathpix OCR API 设计，支持提交 PDF、轮询状态、下载 DOCX 和保存 Mathpix `tex.zip` 公式识别结果包。
- Word 公式预检、OMML 依赖检索、MathType 格式化、宏顺序执行的 API 合同。
- 公式报告支持来源、位置、LaTeX、MathML、置信度、状态明细和默认输出偏好；设置页可配置公式输出格式、字体、字号、编号方式、低置信度阈值、处理策略和是否保留公式原图。
- 公式页支持导出公式 ZIP，包含 `formulas.tex`、`formulas.mml`、逐条公式文件和 `manifest.csv`。
- OMML 转 MathType 任务会检索 OMML 依赖文件，按复制策略放到当前 Word 文档目录，并写入报告。
- 宏处理支持用户选择宏、调整顺序、保存/加载顺序模板、确认风险、创建备份、执行超时、批量执行控制、禁用宏执行队列、白名单宏控制、从任务中心恢复宏执行前备份，并生成本地客户端待执行队列。
- 微小图片检索会从 Word/PPT/Excel 的 OOXML 媒体目录提取真实图片，读取尺寸并按阈值生成缩略图和报告；设置页可控制最大面积、页眉页脚、水印、透明图、重复图和导出格式。
- 图片报告支持按报告导出图片 ZIP 与清单，并可在图片页标记误判、删除待处理和替换待处理。
- 公式/宏/图片/质量报告的结构化输出，质量检查覆盖文件校验、结构数量、公式置信度、OMML 依赖、宏执行、微小图片、转换输出和 Mathpix 状态，支持 HTML、JSON、PDF、XLSX、TXT 下载。
- OCR 设置支持文字 OCR、公式 OCR、表格 OCR、语言、精度模式和速度模式；PDF 转 Word 的 Mathpix 请求会携带这些设置，全部 OCR 关闭时不会上传文件。
- 报告中心支持独立下载失败清单 CSV，覆盖文件校验、批量处理、OMML、宏、转换输出和 Mathpix 失败。
- 任务日志支持页面查看和独立 TXT 导出，任务结果包也会附带任务级日志；日志可按上传、转换、公式、OMML、宏执行分类开关写入。
- 系统设置和本地客户端连接状态展示。
- 系统维护支持设置历史/日志保留天数，并清理旧任务、旧报告、日志、输出、备份和图片缓存，不删除上传源文件库。
- 本地 API 支持安全令牌；令牌留空时不拦截，设置后 JSON 请求、上传和下载都需要携带令牌。
- 结构化安装画像接口 `/api/install-profile`，按 Windows/macOS 展示安装包、必装组件、预检项、任务分流和 MathType 兼容风险。
- 本地连接设置支持网页唤起本地客户端授权、任务状态云端同步授权、敏感文档本地优先和云端同步总开关。
- 任务中心支持按任务打包下载 ZIP，包含任务 JSON、日志、报告和转换输出。

## Mathpix PDF 转 Word

PDF 转 Word 的识别引擎设置为 Mathpix。出于 PRD 的隐私和第三方上传安全要求，系统不会默认上传文件；需要在设置页开启“授权外部上传”，并在运行服务的环境里配置：

```bash
export MATHPIX_APP_ID="你的 APP ID"
export MATHPIX_APP_KEY="你的 APP KEY"
```

如果开启“等待识别完成”，任务会轮询 Mathpix 状态并在完成后下载 DOCX 到当前输出目录的 `{task_id}/` 子目录，同时保存 Mathpix `tex.zip` 公式识别结果包。DOCX 和公式包都会写入标准转换输出，可在任务中心直接下载或随任务结果包一起打包。系统还会从 Mathpix 的 `.tex` 文件中提取 PDF 公式，写入公式报告和统一公式导出包。

## OMML 依赖检索

Word 文档检测到 OMML 公式后，`公式预检`、`OMML 转 MathType`、`Word 转 PPT` 和 `MathType 格式化` 任务会尝试查找 `OMML2MML.XSL` 等 OMML 依赖文件。检索范围包括当前文档目录、K12 运行目录、常见用户目录和设置页填写的自定义路径；也可以在设置页手动指定一个 OMML 依赖文件。复制策略支持覆盖、跳过和自动重命名。

## Word 宏安全队列

宏处理默认不会在网页端直接执行 Word 宏。用户可以在宏页选择宏并调整顺序，把常用顺序保存为模板，确认风险后创建任务；系统会先备份本地 Word 文件，然后把宏队列写入报告，状态标记为“待本地客户端执行”。后续接入 Windows 本地客户端后，可由本地 Office COM 执行队列。

设置页可以关闭宏检测、关闭宏执行队列、按当前文档宏/模板宏/本地宏库分别授权，或启用“仅允许白名单宏”。宏被禁用、来源未授权或不在白名单时，系统只写入安全报告，不创建执行前备份，也不会把该宏交给本地客户端。

任务中心的“恢复”按钮会把宏执行前备份复制回原文件路径。恢复只接受 `.k12-data/backups/` 下由当前任务记录的备份文件，避免任意路径覆盖。

## 系统维护

设置页可配置自动清理临时文件、历史保留天数、日志保留天数和清理周期天数。开启自动清理后，本地服务启动时会检查上次清理时间，超过周期才执行清理。手动“清理历史”会删除超过保留期的任务、报告、日志、报告文件、输出目录、宏备份目录和图片缓存目录，但会保留文件库记录、上传源文件和外部原始文档路径。

## Windows 与 macOS 安装差异

设置页可选择本地客户端平台，并会即时刷新安装画像。Windows 安装画像优先使用 Microsoft Office COM、pywin32 和 Windows MathType 自动化；macOS 安装画像会标记 Office 自动化受限，优先走本地文件分析、人工确认和公式兜底格式。Windows 与 macOS 的 MathType 公式对象不通用，跨平台交付建议同时保留 MathML、LaTeX 或图片兜底。

## 本地 API 安全

默认监听 `127.0.0.1`，设置页的“本地安全令牌”留空时保持无令牌模式。填写令牌并保存后，前端会把令牌保存在浏览器本地存储，后续 API、上传、报告下载、图片资源和任务打包下载都会自动携带该令牌。
